Review Pipeline Health

How a delivered card travels through post-processing — and where that journey can silently stall. This page states the observed behavior (IST), the target design (SOLL), and links every gap to its tracked card. Subordinate documents in review-pipeline-health/ hold the decision history, incident experience and the open-issues home.

§1 · THE PIPELINE — WHERE WORK FLOWS AND WHERE IT WAITS

One delivery, two queues, one serial gate

4-auto-review queue every finished run enqueues here · durable lane state on disk
entry order = scan order, not age
Admission concurrent-card slots · derived from capacity (cores/2, clamped 3–12)
per card the step chain stays sequential
Step chain build/test gate → aspect reviews → grade → orchestrator decision
machine-wide gate lock · serial

Admission decides how many cards post-process concurrently; the build/test gate is machine-wide serial regardless. A card holding an admission slot while waiting for the gate blocks nothing inside its own chain — but it does hold the slot. When all slots are held by gate-waiters, the queue behind them starves, however many cards are ready.

§2 · IST ↔ SOLL — THE FOUR MECHANISMS

Admission

IST

Derived slots, FIFO order

  • Cap derived from capacity (cores/2 → 8 on the operator machine); a fixed PostProcessing:MaxParallelism override silently beat the derivation until 2026-07-23.
  • Queue order = workspace scan order: whole projects can wait behind another project's backlog.
  • Gate-waiting chains hold general slots.
delivered: b99b7ecf · override removed 23.07.
SOLL

Two pools, oldest first

  • build pool (coding runs + gates) and api pool (LLM steps) are admitted separately — a gate-waiter never consumes an api slot.
  • Admission by lane age with project fairness: the oldest waiting card goes first.
  • Latency (run finished → post-processing done) is a first-class metric.
AGT-2222 (remainder) · AGT-2229

Build/test gate

IST

Canonical remote review steps

  • Canonical Remote runs mint an immutable ReviewSubject at the Result-SHA.
  • A Review Host claims the separate ReviewAttempt under lease, fence, authority epoch, capability, and idempotency checks.
  • Tool gates and semantic aspects execute in a disposable exact-subject workspace. Their reports project into the ordinary pipeline and timeline evidence formats.
  • Infrastructure-only failures use the bounded ReviewAttempt retry chain. Stale reports and cleanup writes are rejected by the active fence.
  • The direct SSH gate bridge and its local fallback were removed by AGT-2262 on 01.09.2026 after the claimable path became canonical.
delivered: AGT-2182 · AGT-2229 replacement line · AGT-2262 teardown
SOLL

Current operating invariants

  • Every remote gate command names its expected Result-SHA and reports its actual HEAD.
  • Remote tool execution is visible through ReviewAttempt and pipeline-step facts, never inferred from an SSH alias or a process-local gate counter.
  • The local in-process gate remains only for legacy local review. It does not dispatch work to a remote host and is not a fallback for canonical Remote Review.
contract: ReviewContracts · RemoteReviewExecutor · RemotePipelineReviewEvidenceProjector

Claims & leases

IST

A claim is just an entry

  • Nothing verifies that a living process backs a claim: three cards held host slots for 9+ hours with no process and no worktree (23.07.), starving 12 ready cards.
  • Healing is manual (operator zombie-heal moves).
observed: CAC-6/10/14 zombie leases
SOLL

Heartbeat leases with self-expiry

  • Every claim carries a lease the host must actively renew; no living run → the lease expires and the slot frees itself.
  • Typed abort causes and capability health drive targeted drain instead of blanket stalls.
AGT-2182 · AGT-2185 · AGT-2186

Verdicts & operator authority

IST

Stale artifacts outrank the operator

  • Re-processing derives its verdict from leftover artifacts (consumed attempt ledger, escalation status corpse) — an explicit operator requeue is instantly re-escalated without any new evidence (requeue ping-pong).
  • A passing grade that names defects can close a card without any reaction to the findings.
observed: AGT-1934 / 2110 / 2199
SOLL

Attempt epochs & the council loop

  • A manual move out of an escalated lane bumps the attempt epoch: old budget becomes history, evaluation starts fresh; automatic moves never bump — loop protection stays intact.
  • Escalation artifacts rotate into history on operator requeue; a new escalate is only valid on post-requeue evidence.
  • Council: the orchestrator reacts to every named review finding — fix now (targeted follow-up round), accept with reasoning, or escalate — visibly at the review entry.
AGT-2260 · AGT-2253
§3 · FAILURE CLASSES — WHAT ACTUALLY WENT WRONG (NIGHT OF 22./23.07.)

Four traps, one family: derived state without a feedback loop to reality

Stale-branch trap

Gates ran the card branch's old test suite; develop-side fixes (MachineBound taggings) never arrived. Cards looped gate-fail → reissue on the same old base — one card reached 46 transitions.

fix: build-profile filter (immediate) · AGT-2258 (structural)

Gate wedge

A gate acquired the lock, prepared its workspace and then hung before spawning any process. No watchdog fired for 2.5 h; a dozen queued gates timed out and burned card budgets.

AGT-2257 (watchdog + honest infra failures)

Zombie leases

Dead claims blocked host slots for 9+ hours; a whole project's ready column starved while the system reported the claims as healthy.

AGT-2182 / 2185 / 2186 (heartbeat leases)

Silent starvation & overrides

A forgotten MaxParallelism=3 override pinned admission; FIFO order kept the oldest cards (20 h wait) unprocessed. No sensor reported any of it.

override removed · AGT-2259 (health sensors) · AGT-2222 (fairness)

Two further defects surfaced while fixing: the lane move can report Success while the source folder survives (AGT-2255), and build-profile validation launches bash on Windows and always fails, silently blocking pickup (AGT-2256).
