Version selection

Narrative always opens the newest complete reading

For the active round, POST replaces PRE only after its schema and source references pass validation. Until then, the toggle opens PRE and says that POST is pending. §2 · Proactive generation and cache

The pipeline pays before the reader arrives

Lazy-on-open is rejected. Narrative work runs as ordinary visible pipeline steps in the API pool, never in a build slot. Each step records model, tokens, price, duration, source state, and outcome through the existing pipeline cost contract.

Visible step contract

PRE narrative runs after qualification or preparation. POST narrative runs after review and verdict. Later material refreshes use the same contract. A matching cache digest records a skipped, zero-token step instead of calling the model again.

Material state digest

Regenerate meaning, never duplicate it

taskKey + bodyRevision + reviewCycleId + verdictId + evidenceManifestDigest + templateVersion + generationPromptVersion + modelId

A new round, verdict, materially edited task body, or changed selected evidence creates a new version. Lane timestamps, unread flags, token counters, and repeated status heartbeats do not.

Minimum refresh points

PRE and POST are the floor

PRE runs after qualification or preparation. POST runs after review and verdict. Reissue, escalation, and merge may add refresh steps when their digest changes the reading.

Resource class

API work cannot block builds

Every narrative step declares the API resource class. It competes with bounded model calls, not coding runs or build gates. A project can cap narrative concurrency independently.

Storage and images

Cache outside the task; reuse evidence

The extractor supplies an allow-listed manifest of existing results/ images. The model may select an evidence reference and write its caption, but cannot emit paths or image markup. The app-owned cache does not mutate the task it describes. If no source image exists, the renderer uses a deterministic flow or before/after snippet and labels it explanatory.

No pipeline-panel mockup in this concept

The behavior is specified; the visual is intentionally deferred

Each generation or refresh is an ordinary named pipeline row with its own token and price disclosure. This Workbench concentrates visual judgment on the reports and the head-level mode switch, where the concept still has to prove itself.

Model policy

Mini writes intent; Terra reads evidence

PRE is short, early, and source-light, so Mini is the economic default. POST must reconcile verdicts, open issues, numbers, and evidence references, so Terra is the safer initial default. Sol requires an explicit complexity rule or a failed fidelity retry.

Quality gate

Earn the cheaper POST

Evaluate a 20-card golden set. Require zero invented states, source support for every material number, valid schema on 99% of attempts, and at least 95% open-issue recall before moving POST from Terra to Mini.

§4 · Fixed template

The model writes meaning, never presentation

AHP Deck / Panel v1 owns spacing, type, theme tokens, section order, image slots, and three deterministic diagram primitives. The generator returns only validated, source-linked content.

Required section 01

What is this about?

One plain-language problem statement. Explain domain terms the first time they appear.

Required section 02

What was done?

The smallest accurate account of the change, grouped by outcome rather than file list.

Required section 03

What does the evidence show?

Measurements, verdicts, tests, screenshots, and links. No unsupported “looks good”.

Required section 04

What remains open?

Unfinished work, uncertainty, and follow-ups. If nothing remains, say so quietly.

Renderer-owned primitives

Visual anchors come from a closed vocabulary

  • Flow: 2–6 semantic nodes and directed relations.
  • Before / after: two states and one measured change.
  • Timeline: 2–7 dated events with one current-state marker.
  • Evidence image: one allow-listed results/ reference plus caption.
Language policy

Short, literal, calm

Prefer concrete verbs, define concepts, keep paragraphs short, and reserve warning color for a currently open issue. Historical failures render as history, not an alarm.

AGT-2222 · Implementation

Make review work move while the queue is busy

Post-processing was admitted too narrowly and build gates were serialized on one local machine. Two delivered tranches restored throughput. The permanent fair, host-owned design is still open.

STATE · ROUND 2 · POST READY GENERATED · 23 JUL 2026 · 14:10 READING OF · T1 + T2 DELIVERED VERDICT

What is this about?

After a coding run, several checks still have to review, build, and test the result. That work had become a second queue: only three tasks entered at once, and their build gates then waited 15 to 27 minutes for one local lock.

During the night of 22 July, the review lane grew from roughly 55 to 65 cards while only one card drained. The system had capacity, but its admission and execution model could not use it.

What was done?

  • Post-processing admission now derives from machine capacity instead of a fixed value of three.
  • The supporting-model call budget rose from 30 to 120 calls per hour.
  • Build gates first use two remote-host slots and test the exact subject SHA in a disposable worktree.
  • A remote infrastructure problem falls back to the local gate path.

  • Replace the SSH bridge with claimable remote gate steps owned by the host orchestrator.

AGT-2135 · Small UI change

Keep the active tab in view

When the Studio tab strip is wider than the window, activating a new, existing, or neighboring tab asks the browser to reveal it at the nearest edge.

STATE · ROUND 1 · POST READY GENERATED · 24 JUL 2026 · 03:30 CEST READING OF · ARCHIVED TASK + RESULTS

What is this about?

The Studio can hold more open tabs than fit in the horizontal strip. A tab could become active through a click, a programmatic change, or reopening, while its label remained outside the visible area.

What was done?

The tab state now advances an activation revision whenever a tab is opened, selected, or exposed after its neighbor closes. The shell reacts after Angular renders the tab list and calls the browser's smooth nearest-edge scroll for the active element. This also catches reopening a tab that is already active but was manually scrolled away.
