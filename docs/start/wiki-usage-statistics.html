Post-step pipeline

After an agent run completes, a post-step reads the run transcript, tool-use events, file patches, and final response metadata.

Every document path is normalized to a docs-root-relative path, for example architecture/bus/agent-message-bus.md.

The post-step classifies each document as visited, used, or changed.

It writes a task-local task-wiki-usage.json and updates a project aggregate wiki-usage-index.json.

The Wiki right panel can show usage by document. The task processing view can show the inverse list of documents used by that run.

Important distinction

A search hit is only visited. A document becomes used when the run output, patch, report, or decision clearly relies on it. This avoids inflated statistics from broad searches.

Classification rules

visited

Read, opened, searched, previewed, or matched by a tool. Useful for heatmaps and stale-doc discovery.

used

Quoted, summarized, referenced in a report, or used as rationale for a code/task decision.

changed

Edited, created, moved, deleted, or generated by the run. This is the strongest signal.
