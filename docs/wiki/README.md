# Project Wiki

Structured knowledge base for the agent-taskboard project. This is a first-class citizen in the repository, not an afterthought.

## Structure

| Folder | Purpose |
|---|---|
| [common-problems/](common-problems/) | Known recurring problems with root-cause analysis, occurrence logs, and workarounds. **Search here first** when a familiar symptom appears. |
| [learnings/](learnings/) | Per-task run learnings auto-distilled by the opt-in `post-wiki-learnings` pipeline step: derived verdict, review findings, stumbling blocks, agent notes, and what changed. One page per task; `README.md` is the auto-generated index. Do not edit by hand. |
| [decisions/](decisions/) | Architecture Decision Records (reserved for Phase 2 migration from `docs/architecture-decisions.md`). |
| [glossary/](glossary/) | Term definitions (reserved for Phase 4). |
| [conventions/](conventions/) | File naming, test naming, commit conventions (reserved for Phase 4). |

## Searching

Find a known problem by symptom:

```sh
grep -ril "<symptom>" docs/wiki/common-problems/
```

Or use the frontmatter tags:

```sh
grep -rl "tags:.*eacces" docs/wiki/common-problems/
```

The [common-problems/README.md](common-problems/README.md) index is auto-generated by `scripts/wiki/regenerate-index.sh`. Do not edit it by hand.

## Conventions

### Problem folders

Each problem lives in its own folder under `common-problems/<slug>/` with these files:

| File | Content |
|---|---|
| `README.md` | Executive summary with YAML frontmatter (required). What, when first seen, current status. |
| `occurrences.md` | Timeline of every observed occurrence (UTC, task ID, agent, affected path). |
| `protocol.md` | Root-cause analysis, reproducers, log excerpts. |
| `measures.md` | Fix attempts with status (tried / applied / works / failed). |
| `ideas.md` | Hypotheses, open questions, discarded approaches. |
| `related.md` | Cross-references to other problems, tasks, ADRs. |

### Frontmatter (required on every README.md)

```yaml
---
id: <slug>
title: "<one-line description>"
status: open | mitigated | fixed | archived
first-seen: <ISO-8601 UTC>
last-seen: <ISO-8601 UTC>
severity: blocker | major | minor | nuisance
category: permission | filesystem | cli | runner | ui | state-machine | misc
tags: [<keyword>, ...]
affects:
  - "<path or feature>"
related-tasks: []
related-adrs: []
---
```

### Status values

- **open** - actively occurring, no reliable workaround.
- **mitigated** - workaround exists, root cause not fixed.
- **fixed** - root cause resolved. Keep for 30 days, then move to `archive/`.
- **archived** - historical reference only.

### Lifecycle

1. Symptom appears. Search `common-problems/` for a match.
2. Match found: add an occurrence entry to `occurrences.md`, apply known measures.
3. No match: create a new folder via `scripts/wiki/new-problem.sh <slug>`.
4. When fixed: set `status: fixed`, update `last-seen`, note the fix commit in `measures.md`.
5. After 30 days with no recurrence: `git mv` the folder to `common-problems/archive/`.

### Cross-linking

Use `[[slug]]` to reference other problem entries. These are plain-text markers for grepping, not rendered links.

### Scripts

| Script | Purpose |
|---|---|
| `scripts/wiki/new-problem.sh <slug>` | Scaffold a new problem folder from template. |
| `scripts/wiki/lint.sh` | Validate frontmatter on all problem READMEs. |
| `scripts/wiki/regenerate-index.sh` | Rebuild `common-problems/README.md` from frontmatter. |
