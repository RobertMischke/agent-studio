Pflege-Regel

Diese Seite ist der eine Ort, an dem Vorfälle der Ausführungs-/Review-/Gate-Kette dokumentiert werden. Jeder neue Vorfall bekommt einen Eintrag im Format unten (Problem → Root Cause → Maßnahme → Status → Referenzen) bevor die Karte dazu geschlossen wird. Ein Vorfall ohne Eintrag hier gilt als nicht aufgearbeitet.

Die Phantom-Welle

11.07.2026, abends
Problem
~29 Karten der Abendwelle als „done“ gemeldet, aber auf origin kam kein einziger Commit an. xhigh-Compute-Arbeit unwiederbringlich zerstört (kein dangling commit auffindbar).
Root Cause
Drei gleichzeitige Defekte („die drei Löcher“):
  • AGT-2149: Host ohne Git-Push-Credentials (Deploy-Keys per Org-Policy deaktiviert) — jeder Push scheiterte.
  • AGT-2148: Daemon-Prompt ohne Completion-Protocol → nie ein Terminal-Sentinel → outcome Unknown → serverseitig als „Completed out-of-band“ verbucht (Erfolgs-Default für ein unbekanntes Ergebnis).
  • AGT-2147: Teardown machte worktree remove --force ohne Commit/Push — und lief nach der bereits gemeldeten Completion, Fehler verschluckt.
Tiefenstruktur: Completion war zeitlich vor und logisch unabhängig von jedem Push.
Maßnahme
Reihenfolge invertiert und gegated: Teardown committet, pusht, verifiziert (ls-remote-Gegenprobe) — erst dann Complete mit SHA. Push-Fehler ⇒ WorktreeSalvageException, Worktree bleibt, Karte eskaliert statt „done“. Startup-Push-Probe; schreibunfähige Runner melden sich read-only, Claims werden verweigert. Deploy-Key-Policy geflippt, Key am Repo.
Status
deployed 12.07. — Heilungsbeweis: AGT-2123 lief danach komplett durch (outcome Done, salvage-push secured=True).
Referenzen
AGT-2147/2148/2149 · runner/GitWorkspace.cs, runner/RemoteTaskRunner.cs, runner/GitPushProbe.cs, runner/SentinelScanner.cs · Handoff lage-kontext-handoff-2026-07-12.md

Gate-Test-Stufe wird Falsch-Eskalations-Fabrik

12.07.2026
Problem
Mit dem Nacht-Deploy bekamen Karten-Gates eine Test-Stufe — und vier latente Rot-Quellen (Namespace-Guard, monatslatente Fixture, Label-Drift, Live-Checkout-/Perf-Polizei) ließen gesunde Karten reihenweise durchfallen. Zusätzlich: Gate-Timeout 300 s bei ~8 min Suite („exit n/a“ = Timeout, kein roter Test), BuildProfile-Validierung läuft im leeren Worktree-Kontext (MSB1009) und blockiert Auto-Pickup.
Root Cause
Maschinen-/lastabhängige Tests in parallelen Karten-Gates; Timeout-Default nicht an Suite-Dauer angepasst; Validierung gegen falschen Kontext.
Maßnahme
MachineBound-Konvention ([Trait("Category","MachineBound")]) + Gate-Filter Category!=MachineBound; Timeout auf 900 s; Workaround: Status direkt in project-settings.json auf pipeline-ready.
Status
Workarounds aktiv Validierungsbug offen — strukturelle Antwort ist die Hermetik (Hauptseite §5).

Die Grade-D-Welle: Salvage nie integriert

17.07.2026, 20:03–21:52
Problem
Auto-Review eskalierte 17 Karten mit Grade D — „the claimed implementation exists only on an external salvage branch“. Die Reviews waren korrekt: die Arbeit lag auf runner/agent-runner-01/*, die reviewten task/*-Branches waren leer oder themenfremd.
Root Cause
Design-Lücke, nicht Bug: der Remote-Runner pusht ausschließlich auf runner/<id>/<key>; kein automatischer Schritt integriert nach task/<slug>. Der Review-Diff-Scope (Run-SHAs → Branch-Fallback) rät und trifft im Phantom-Fall das falsche Universum. Detailanalyse: Hauptseite §2.
Maßnahme
Reconciliation aller 19 betroffenen Karten: frischer task/<slug> von aktuellem develop, merge --squash des Salvage, Konflikte develop-erhaltend gelöst, Push, Requeue. Strukturelle Antwort: Result-SHA-Vertrag (Phase 1).
Status
Reconciliation erledigt Struktur: Phase 1 gequeued

Workstream-Frame nicht bewährt — Rückbau

19.07.2026
Problem
Der fixe Engineering-Workstream-Frame (5 unveränderliche Wiki-Areas mit Landing-Shells, Baum-Pinning, Collector-/Curator-Pipeline) hat sich in der Praxis nicht bewährt. Drei Kernbelege der Evidenz-Analyse:
  • 0 Inhalt: nach 10 Tagen und ~200 Tasks lag unter dem Frame keinerlei operator- oder agentengeschriebener Inhalt — nur die 6 gesäten Shells.
  • 0 Leser: 0 von 575 untersuchten Task-Logs lasen jemals eine Frame-Seite.
  • Bedarf woanders: der reale Wissensbedarf materialisierte sich in learnings/, common-problems/ und den Workbenches — nicht im Frame.
Operator-Entscheid: „nicht bewährt, umbauen".
Maßnahme
Mittelweg-Schnitt: (1) Pulse-Drift gradet jetzt die realen Top-Level-docs-Ordner mit Seiten (Reihenfolge = gespeicherte wiki-order, sonst alphabetisch); Feed-Area-Badges = Top-Ordner. (2) Das human-action-Signal überlebt als ordnerunabhängige Frontmatter-Konvention (human-action: + status: observed|active), dokumentiert in contracts/wiki-tree.md. (3) Toter Stack entfernt: docs/engineering-workstream/-Shells, Seeder/Frame/Content-Klassen, WorkstreamCurationService, post-workstream-collector + pre-workstream-onboarding aus dem Pipeline-Katalog, Prompt-Template, Frame-Pinning/-Immutabilität in Baum & Endpoints, Frontend-Pin/Lock-UI. Konzeptseite concepts/engineering-workstream.md trägt ein Überholt-Banner + Sidecar status=ueberholt; Einstiegs-Kuration übernimmt die kuratierte Startseite (home.json-Seeds der Konsolidierungsanalyse).
Status
done — Backend-/Frontend-Umbau umgesetzt, Suiten grün.
