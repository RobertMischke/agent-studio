A local telemetry layer across every organization application

A shared event contract lets locally used applications report behavior and failures into Agent Studio. A bounded orchestrator consumer turns repeated, evidenced patterns into feature, healing, or decision work without making the event stream itself a workflow engine.

§1Decision in one page

Recommendation

Adopt the hybrid option: every application writes a small, append-only local JSONL outbox first; an Agent Studio collector tails or receives that outbox over an authenticated local endpoint; Agent Studio stores the normalized runtime facts on disk, projects qualifying signals onto the existing Agent Message Bus, and pushes read-model updates to the UI through its existing SignalR hub.

The raw runtime stream remains passive evidence. A separate rules and case layer consumes bus messages and may call existing application boundaries to prepare a card, append an Activity item, request a decision, or invoke a pre-approved bounded recovery. Every action has a fingerprint, evidence references, a budget, a receipt, and a terminal.

Reuse, do not restart

Agent Studio already has the ProductRuntimeEvent envelope, runtime JSONL capture, a project runtime panel, the file-backed Agent Message Bus, token projections, and SignalR fan-out. The new work is cross-app identity, local ingestion, policy, and action receipts.

Keep authority explicit

Telemetry records facts. The orchestrator owns policy. Task creation uses the Task API or the same application service behind it, never direct task-folder writes. Existing runner and Git authorities remain unchanged.

Inventory conclusion

This repository contains no grounded evidence that Quality Studio, the chat library, the TE website, or voice-lint currently emit this common envelope during ordinary local use. Their rollout status must therefore begin as not integrated, not as “no telemetry exists.” Each pilot starts with a small source-repository inventory before selecting event names.

Fail-open application behavior

Telemetry must not break the product action it observes. Producer serialization or transport failure writes one bounded local diagnostic and continues. The exception is audit-grade security events explicitly designated by a product's own policy; this dossier does not create such designations.

§4Local-first privacy posture

Local-first means no default egress. App outboxes, the collector, Agent Studio's runtime store, the Agent Message Bus, rules, cards, and Activity projection all operate on the same machine or explicitly configured private local network. There is no cloud broker, vendor account, analytics SDK, or background upload dependency.

Never enter telemetry

  • Secrets, credentials, access tokens, cookies, authorization headers, or encryption keys.
  • Prompt bodies, chat messages, source code, diffs, file contents, clipboard contents, or free-form form values.
  • Email bodies or addresses, voice audio, voice transcripts, contact data, or user-authored website content.
  • Full URLs with query strings, raw database statements with values, or unbounded request and response bodies.
  • Stable device fingerprints or external user identifiers.

Allowed with controls

  • Stable event and feature keys, coarse route templates, outcome codes, durations, counts, and bounded error types.
  • A local pseudonymous actor id when cross-session deduplication is required. It never leaves the local installation.
  • Truncated stack data in the local raw stream. Bus signals carry a fingerprint and artifact reference, not the stack.
  • Explicit task, run, and artifact references already governed by Agent Studio's evidence model.

Redaction happens at the producer before the first disk write. The collector validates an allowlist and rejects or quarantines unknown oversized fields. Local HTTP binds to loopback or a local socket, authenticates the app registration, and does not listen on a public interface by default. Per-app retention is visible and configurable; deletion removes local telemetry and derived cases only according to a documented evidence-retention policy.

Hybrid contract

  1. The app appends a valid event with a stable eventId to its local outbox before returning from the telemetry adapter.
  2. The adapter batches unacknowledged rows to an authenticated Agent Studio loopback endpoint. File tailing remains available for simple tools.
  3. The collector validates schema and privacy limits, deduplicates by (appId, eventId), preserves original time, and appends to Agent Studio's logs/runtime/<appId>/ stream.
  4. The collector acknowledges the highest contiguous outbox cursor. The app rotates only acknowledged segments after its local retention window.
  5. A signal adapter aggregates and fingerprints relevant runtime facts, then appends a small AgentMessage with a runtime-event artifact reference. It does not copy the raw payload.
  6. Agent Studio's existing SignalR path fans the bus update to connected UI clients. Reconnect always rehydrates from disk-backed projections.

§6How the orchestrator turns events into action

The action loop follows the Global Orchestrator Watcher dossier, AGT-2557 / AGT-W15: deterministic sensors first, one durable case per fingerprint, bounded analysis only when needed, explicit authority classes, and Activity as the shared chronological surface. Telemetry broadens the Watcher's trigger catalogue; it does not bypass runner or task policy.

PatternPilot rule and fingerprintActionGuardrails and terminal
Repeated usage friction At least 5 category=friction events across 3 local sessions within 7 days for the same appId + featureKey + reasonCode. Prepare one feature card in Preparation with count, time window, affected versions, and evidence references. Publish an Activity action receipt. No user text. Thirty-day cooldown after dismissal. New evidence updates the existing draft. Terminal: card prepared, operator dismissed, or signal expired.
Error cluster At least 3 Error events within 15 minutes, or one Fatal event. Fingerprint appId + event + error.type/code + normalized-stack-hash + appVersion. Open a Problem case. Prepare a healing card when the evidence is sufficient; otherwise publish needs-decision. A known, approved A1 recipe may intervene once. No automatic code edit. One active case per fingerprint. Recovery events close the case only after a quiet verification window.

Prepare a performance card only after the second breached window. No threshold is inferred from one run. Version change resets the baseline but links the prior case.
Acute operational alarm Fatal, security-designated, route unavailable beyond its grace period, or a Watcher rule with declared acute severity. Persistent Activity Problem plus needs-decision. Existing alarm banners remain reserved for acute current state. Rate-limited transitions, not polling noise. Resolution requires an observed recovery fact and a receipt.

Existing consumers prove the control shape

AGT-2654 is the first productive guardian slice. Visual QA captures exact-checkout screenshots, uses a bounded classifier, lets pure VisualQaPolicy grant exactly one automatic defect steer, counts prior use from durable verdict receipts, and hands repeated or unavailable cases to Human Review. Telemetry-driven actions should copy that control structure: the model may summarize evidence, but pure policy owns thresholds, budgets, and lane-affecting actions.

The same visual-QA and steered-retry machinery becomes a consumer of telemetry rather than a special exception. Its visual-qa-clear-defect and visual-qa-unavailable receipts can enter the Watcher case store; wider telemetry cases can reuse the continuation-note boundary only when an approved recipe and retry budget exist.

§7Agent Studio as the organization operations hub

Positioning

Agent Studio is the convergence point for management layers on top of coding work. It coordinates delivery and promotion, presents telemetry and alarms, runs the orchestrator and guardian policies, and keeps action receipts across all organization products. CI/CD, telemetry, and operations gravitate here because they all need the same project registry, task identity, evidence, authority, and Activity surface.

Agent Studio ownsEach product continues to own
Organization app registry, local ingestion authentication, schema validation, redaction enforcement, dedupe, retention status, and collector health.Where meaningful events occur, stable product event names, feature keys, error codes, product-local redaction, and proportional instrumentation.
Durable cross-app runtime projections, Agent Message Bus signals, Activity, alarms, needs-decision cases, task preparation, and action receipts.Domain behavior and analysis. Quality Studio keeps its analysis core and run semantics; Agent Studio consumes facts and manages resulting work.
Promotion train visibility, exact-SHA gate evidence, actions hygiene, cross-project orchestration, guardian budgets, and operator control.Build and test commands, release artifacts, app-specific health checks, and domain-safe recovery primitives.
Common envelope contract and compatibility tests.Raw sensitive data. The chat library keeps message bodies; voice-lint keeps audio and transcripts; the TE website keeps form content out of telemetry.

Boundary against a central “god service”

  • Agent Studio does not become the runtime dependency for an app to function. Outbox writes are local and fail open.
  • Agent Studio does not execute Quality Studio analyses, interpret chat content, process audio, or own website domain logic.
  • The collector does not become a cloud relay. Remote or production telemetry is a later decision with a separate threat model.
  • The bus remains a record and signal layer, not a workflow engine. Orchestrator actions call existing public application boundaries and leave receipts.
  • CI/CD remains exact-SHA and pipeline owned. Telemetry may detect or explain a problem; it cannot redefine a green gate.

§8Pilot and rollout slices

Recommended pilot: Quality Studio, one friction event

Quality Studio is the best first app because it already has durable run concepts and is already managed as an Agent Studio project, while its analysis core remains a clean product boundary. The pilot emits only analysis.run.retry-requested with category=friction, feature or analysis-mode key, reason code, session id, outcome, app version, and duration. Rollout order after the pilot

  1. Agent Studio dogfood. Convert selected existing signals, starting with GitProcessTelemetry slow operations and one pipeline alarm, into the common runtime fact model without removing their current sinks.
  2. Chat library. Adopt usage and error metadata only. Never emit message bodies, prompts, participant names, or attachments. This proves a reusable library integration across host applications.
  3. voice-lint. Emit rule ids, operation durations, outcome codes, and counts. Audio, transcripts, recognized text, and file contents never enter the outbox.
  4. TE website local preview. Cover local development and preview flows first. Production visitor analytics remain out of scope because they would violate the current local-only decision and need consent plus deployment architecture.
  5. Second categories across all apps. Add error clustering only after each app passes the privacy and replay fixture suite. Add autonomous recovery only recipe by recipe under Watcher promotion evidence.

§9Operator decision request

Approve or amend this package

  1. Architecture: approve the hybrid file-first outbox plus authenticated local push, with Agent Studio as collector and operations hub and no cloud dependency.
  2. Contracts: approve additive evolution of ProductRuntimeEvent for product facts and continued use of AgentMessage for derived signals and action conversation.
  3. Authority: approve passive raw events, deterministic case rules, task creation only through the Task API boundary, and no automatic code edits. Existing A1 recipes remain separately budgeted.
  4. Privacy: approve producer-side allowlist redaction, the explicit never-collect list, local-only actor pseudonyms, and reference-only links to sensitive evidence.
  5. Pilot: approve Quality Studio and the single analysis.run.retry-requested friction event through one deduplicated Preparation card, followed by 30 days of shadow evaluation.
  6. Positioning: approve Agent Studio as the management and operations layer for CI/CD, telemetry, alarms, and orchestration across organization products while domain cores remain product-owned.

Recommended answer: approve all six items. They activate existing file-first observability and bus investments, preserve application independence and privacy, and add action only behind the same durable, bounded policy structure already proven by the visual guardian.

Related contracts: Product Runtime Observability, Agent Message Bus, Global Orchestrator Watcher, UI task iteration and visual QA, and develop to main promotion.
