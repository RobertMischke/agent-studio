Local Telemetry Layer Across Organization Apps

A local-first event layer that turns product usage and operational signals into observable, reviewable action while keeping each product's domain core and raw user data inside its own boundary.

Date 14 August 2026 Source AGT-2661 Status Decision pending Scope Concept only, no implementation

Recommendation

Approve the hybrid local bus: a durable file-first buffer in every app, collected into Agent Studio's existing file-backed Agent Message Bus, with local HTTP ingestion and SignalR used only to accelerate delivery. Start with Quality Studio reliability fallback events. After a threshold is met, the Global Orchestrator Watcher prepares one healing card through the Task API. No cloud service, raw interaction content, or event-triggered direct mutation is part of the design.

§0Decision packet

Decision requested: approve the event contract, the hybrid transport, Agent Studio's management-layer ownership, the Quality Studio pilot, and the rollout order. Implementation remains a separate set of cards.

Transport

Per-app JSONL spool plus local collector push, deduplicated into the existing Agent Message Bus.

Action boundary

Events wake policy. Only existing application APIs may create or move cards, run recovery, or mutate Git.

Privacy

Operational metadata stays local by default. Content, credentials, audio, and identity never enter telemetry.

What this adds

One organization-wide product-event envelope, app registrations, a reliable local collector, event-pattern rules, and a card-preparation receipt.

What already exists

Agent Studio already has JSONL evidence, a file-backed bus, in-memory projections, REST queries, TaskHub SignalR fan-out, and a Watcher architecture.

What this does not become

Not a cloud analytics service, workflow engine, generalized event broker, product-domain database, or replacement for test and review evidence.

Success condition

One repeated local Quality Studio failure pattern results in one deduplicated, evidence-linked healing card visible in Agent Studio.

Log-level mapping

Structured logging is the practical seam, but log level alone is not an event contract. An adapter may promote only rows that carry a registered event.name and telemetry.emit=true, or that cross a centrally configured operational threshold.

Source log levelDefault bus behaviorReason
TraceLocal log onlyHigh volume and often content-adjacent. Never emitted by default.
DebugLocal log onlyEligible only in an explicit diagnostic capture window with the same privacy filter.
InformationAllowlistEmit registered usage, workflow, performance, and lifecycle events. Ordinary informational prose remains a log.
WarningEmit and groupEmit sanitized registered events, then deduplicate and rate-limit by fingerprint.
ErrorEmitUse exception type, error code, component, and scrubbed fingerprint. Do not copy exception messages or stack traces into the event.
CriticalEmit acuteWake acute incident policy immediately, while retaining the same dedupe and authority guards.

Explicit domain events may bypass logging when their semantics are not a log level, for example feature.used, workflow.abandoned, or review.completed. They still use the same local spool and envelope. This keeps usage intent clear and prevents teams from inflating log severity merely to reach telemetry.

The ingestion adapter maps telemetry severity to the current Agent Message Bus without adding a new severity: info becomes Info, warning becomes Warn, and both error and critical become High while the original severity remains in the versioned payload. Categories map to existing bus kinds: reliability and security failures use error; explicit actions use intervention; lifecycle uses lifecycle; all other bounded product signals use observation. Stable event name, not bus kind, remains the rule key.

§3Privacy posture: local first and content free

Default: telemetry is stored and processed on the same machine or explicitly configured local network as the apps. There is no cloud exporter, third-party SDK, remote analytics account, or automatic organization-wide upload.

Data that never enters the shared telemetry layer

  • Prompt, chat, email, editor, form, clipboard, and comment contents.
  • Source code, diffs, file contents, model responses, review prose, screenshots, or generated artifacts. Events may carry local references and hashes.
  • Credentials, API keys, access tokens, cookies, authorization headers, connection strings, or provider session material.
  • Voice audio, derived transcripts, biometric features, speaker identity, or raw voice-lint input.
  • Full URLs with query strings, arbitrary search text, absolute home paths, IP addresses, device fingerprints, account names, or email addresses.
  • Unbounded exception messages and stack traces. Raw errors stay in the source app's access-controlled log.

Enforcement

  • Emitter allowlist: each registered event declares allowed attributes, measurement units, cardinality, and privacy class.
  • Collector scrub: a second independent policy rejects secret patterns, absolute paths, unknown attributes, and oversized values before central append.
  • Fail closed for privacy: an invalid event stays out of the organization bus and produces a rate-limited local diagnostic counter, never a copy of the rejected payload.
  • Local export is explicit: any future support bundle is a separate operator action with preview, redaction report, bounded time range, and destination confirmation.
  • Retention: unacknowledged source spools are size-bounded but never discarded silently. Acknowledged source rows may rotate after 14 days; central bus retention follows the existing workspace hygiene policy. These defaults are implementation decisions to ratify in Slice T0.

Hybrid contract

  1. The emitter validates and appends the sanitized event to its app spool before returning. Telemetry failure never blocks the user action, but increments a local health counter.
  2. The collector reads after its last acknowledged offset and sends a bounded batch to a loopback or configured local-network Agent Studio ingestion endpoint.
  3. Agent Studio validates app registration and privacy, deduplicates by event id, maps the event to a standard AgentMessage kind and severity, then appends through AgentMessageBusStore.
  4. Only after the central append succeeds does the collector advance the source watermark. Replayed batches are safe. SignalR then broadcasts the accepted bus message.
  5. The source app's raw log remains its diagnostic truth. The normalized bus row is the accepted cross-product event truth. They are linked by event id or a local evidence ref, not treated as competing copies.

The adapter should map source.appId to a participant such as runtime:quality-studio, map categories to existing bus kinds, and preserve the full telemetry envelope under a versioned payload until an additive sourceApp bus field is approved. This avoids a breaking change to current bus readers.

§5Orchestrator consumption: event to action

The orchestrator consumes patterns, not isolated events. A rule owns its source names, grouping key, time window, minimum distinct sessions or occurrences, cooldown, action class, required evidence, and resolution condition. Model analysis may summarize a prepared case, but pure policy decides whether a card may be created or an intervention may run.

Guardian and visual-QA alignment

The Global Orchestrator Watcher dossier (AGT-2557, AGT-W15) already defines a durable case, observe-first rollout, bounded action allowlist, Activity projection, and decision-required terminal. This telemetry layer supplies a broader family of typed producer inputs. It does not create a second guardian.

AGT-2654 visual QA and steered retry is the reference consumer shape already in code: exact-worktree screenshots and verdict.json form durable evidence, VisualQaPolicy grants at most one automatic defect steer, and repeated or unavailable verdicts reach Human Review. The telemetry layer should mirror exhausted visual-qa-clear-defect and visual-qa-unavailable receipts into Watcher cases. It must not turn every acceptable visual verdict into a high-volume event.

Card creation receipt

Every telemetry-prepared card uses an idempotency key telemetry-rule-id + source-app + fingerprint + window-start. Its body states the observed aggregate, confidence, privacy-safe reproduction context, source versions, related bus ids, local evidence references, and why the threshold was crossed. The receipt stores the created task key and rule version. If the Task API is unavailable, the case stays prepare-pending and retries with bounded backoff. Direct writes under task workspace folders remain prohibited.

Rollout order after the pilot

  1. Quality Studio pilot. Proves a standalone local app, browser and backend seams, offline buffering, cross-process collection, a reliability pattern, and one healing card.
  2. Agent Studio dogfood. Migrate only summarized Git performance, prompt-health, runner, pipeline, and CI/CD management signals that are not already canonical bus events. This proves self-observation and collector-health alarms.
  3. Coding Agent Chat. Add content-free transport and rendering events, plus owner routing back to the library project. Run a dedicated privacy review before enablement.
  4. Token Economy website. Add local client reliability and performance. Do not silently turn this into public visitor analytics.
  5. voice-lint. Add rule and runtime metadata only after a stricter audio and transcript privacy threat review. The emitter must be testable without any original media in fixtures.

Rollout gates

  • No app proceeds until its event registry and never-collect list are reviewed.
  • Per-app spool health, rejection count, lag, oldest unacknowledged event, and central append failures must be observable locally.
  • Card precision is reviewed after the first 10 eligible cases. A false or low-value card pauses automatic preparation for that rule, but leaves observation running.
  • Intervention authority does not widen as a side effect of telemetry rollout. Each recovery action needs its own allowlist and verification.
  • Any cross-machine configuration is explicit, authenticated, access-scoped, and still independent of cloud services.

Decision checklist

  1. Approve Option C, hybrid local buffer plus push, as the organization transport.
  2. Approve OrgTelemetryEvent v1 and the structured-log mapping, including allowlisted Information and all sanitized Warning, Error, and Critical registered events.
  3. Approve Agent Studio as the management-layer convergence point for CI/CD, telemetry, alarms, and orchestration.

  5. Approve the rollout order and the rule that no app may send content or depend on a cloud service.
