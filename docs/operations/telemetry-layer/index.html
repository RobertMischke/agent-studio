A local telemetry layer across every organization app

A shared, file-first path from local product behavior to Agent Studio observation, diagnosis, and bounded action, without a cloud telemetry dependency and without moving product ownership into the management layer.

Recommendation

Approve a hybrid local bus: every application first appends a small, validated Product Runtime Event to an application-local JSONL outbox; an Agent Studio collector tails and checkpoints those files, normalizes eligible records into the existing Agent Message Bus, and uses the existing local HTTP and SignalR path only for prompt delivery and live projection. The application file remains the raw truth. The bus is the management projection. SignalR remains acceleration, never durability.

First proof: Quality Studio emits one quality.review.failed category end to end. Three matching failures in 24 hours across at least two run IDs open one Watcher case and create one deduplicated healing card in the Quality Studio backlog. The pilot never starts that card automatically.

Reuse two existing contracts

ProductRuntimeEvent remains the app event. AgentMessage remains the management, Activity, and Watcher event. This is a profile and adapter, not a third envelope.

Rules before models

Stable event names, counters, windows, and fingerprints create findings. A strong model is reserved for ambiguous root cause or card drafting, and cannot grant action authority.

Management layer, not product merger

Agent Studio owns collection, correlation, policy, cards, alarms, and CI/CD receipts. Each product keeps its domain core, raw evidence, and emitter semantics.

Scope boundary

This dossier defines a concept and rollout contract only. It does not change schemas, add an ingestion endpoint, start a collector, create cards, or install telemetry in any product. The current Agent Message Bus explicitly does not move tasks. That remains true: a separate admitted Watcher policy calls the Task API after a rule has produced a durable case.

§2Event model and the structured-logging seam

A telemetry event is a small, immutable fact emitted by one application during local use. It is not a log sentence, task command, or copied transcript. The model reuses the current ProductRuntimeEvent schema and adds a portfolio profile through optional v1 fields. The normalized management projection remains an AgentMessage with a runtime-event artifact reference.

Source appsourceApp.id, component, version, instanceId, environment=localSeparates Quality Studio from Agent Studio and distinguishes two local instances without using mutable display names.

SeverityTrace, Debug, Info, Warn, Error, FatalProducer-local impact. Management projection maps to existing bus Info, Warn, or High.

§3Local-first privacy posture

Local-first means the telemetry plane works with the network disconnected, stores raw evidence on the machine that produced it, and has no vendor or cloud sink. It does not mean that every local payload is safe to collect. Producers minimize and redact before append.

ClassMay enter app-local JSONLMay enter Agent Message BusMay enter model context
OperationalStable event, status, duration, error code or type, relative component, app version.Fingerprint, count, first and last seen, local artifact reference.Bounded evidence pack only when deterministic rules cannot decide.
Usage aggregateExplicit feature action, latency, success or cancel, pseudonymous session.Aggregate counts and friction signal, not raw action history.Aggregated summary only.
Restricted localRaw stack, path, or diagnostic excerpt only when needed and retention-bounded.Reference plus redacted summary, never copied payload.Denied by default; requires an attributable operator action under existing model-provider policy.

Never leaves the machine through this telemetry layer

  • prompts, chat messages, transcripts, clipboard contents, typed free text, and raw document or source-file bodies;
  • voice recordings, audio samples, transcripts from Voice Lint, or biometric characteristics;
  • credentials, bearer tokens, API keys, cookies, provider session files, authorization headers, and quota authentication material;
  • absolute home paths, user names, email addresses, raw URL query strings, or stable cross-product person identifiers;
  • full stack traces, screenshots, review documents, and task evidence as bus payloads. These stay local artifacts and are referenced;
  • any event upload to an analytics SaaS, cloud queue, or external OpenTelemetry collector.

An existing agent or review call may already use a configured external model provider. This dossier does not change that contract. Telemetry does not silently add model calls. When a Watcher case needs analysis, its normal model route, permission, redaction, token accounting, and evidence receipt apply, and restricted-local artifacts remain excluded unless the operator explicitly admits them.

Recommended storage and acknowledgement contract

  • Each product owns <app-data>/telemetry/YYYY-MM-DD.jsonl, schema metadata, rotation, and redaction. The source repository does not receive runtime files.
  • The collector registry maps immutable app ID to approved local roots and privacy policy. No broad home-directory scan or dynamic plugin file discovery is allowed.
  • A checkpoint stores last acknowledged event ID plus source file identity. The central bus deduplicates by source app and event ID, so replay after a crash cannot create a second case.
  • Collector append to the Agent Message Bus happens before its checkpoint advances. HTTP ingestion returns the accepted event IDs, not merely status 200.
  • SignalR publishes only after the bus append. Reconnect reloads a complete snapshot through the existing API.
  • File corruption produces a warnings sidecar and a visible collector-health event. It never discards earlier good rows.
  • Retention is category-based and local. Raw Info usage may rotate quickly after aggregation; cases and their source references follow task evidence retention.

§5From event to orchestrator action

The Watcher vision in AGT-2557 and AGT-W15 supplies the control pattern: mechanical truth first, deterministic inspection second, versioned recovery recipes third, strong analysis only for uncertainty, and an attributable report for every action. Telemetry adds product-originated triggers to that same loop.

Case and card idempotency

Every rule produces fingerprint = hash(ruleVersion, sourceApp, event, normalized dimensions). There is one open case per fingerprint. A card mutation uses telemetry:<rule>:<fingerprint>:<window-start> as its idempotency key. Later matching events update counts and last-seen time; they do not produce feed spam or duplicate cards. A closed card starts a seven-day cooldown unless a Fatal event or a new rule version supplies materially new evidence.

Model routing follows the canonical policy, not the event severity. A bounded summary over compact structured evidence with no action authority may use the supporting-call tier. Ambiguous root-cause analysis or a decision that can authorize a lane-affecting action requires at least the strong Sol/medium tier; correctness-critical security, destructive, or distributed-authority decisions retain the Sol/xhigh floor. Quota never lowers those floors. Every analysis receipt records route, thinking level, evidence scope, and unknowns.

Existing consumers and precedent

  • Global Orchestrator Watcher, AGT-2557 / AGT-W15: already defines bus triggers, evidence packs, recipes, Activity projections, decision-required cases, and an observe-first authority ladder. Cross-app telemetry becomes another typed input, not another supervisor.
  • Visual guardian and steered retry, AGT-2654: already turns exact screenshots and a bounded verdict into one pure-policy retry, counts the prior retry from durable receipts, and then escalates. The telemetry layer may surface those outcomes across products, but it does not grant a second visual retry.
  • Alarm banners: queue starvation and accepted-not-integrated already prove that acute derived signals belong in the workspace shell. Their future bus events should feed the same case stream and retire separate polling only after parity evidence.
  • Review reaction machinery: grade findings already map to one of FixNextRound, Accept, or Escalate with a durable sidecar and decision journal. Telemetry cards should carry the same evidence-to-action trace.

§6Agent Studio as the organization operations hub

The observed convergence is architectural, not accidental. Agent Studio is the management layer on top of coding work across the organization. It already owns task admission, runners, review, evidence, Activity, alarms, Git delivery, and the develop-to-main promotion train. The telemetry layer adds product behavior to the same management view. CI/CD, telemetry, alarms, and orchestration converge here because they all answer one operator question: what across the portfolio needs attention or a decision now?

Product boundaries that remain explicit

  • Quality Studio keeps the review analysis core, review schema, staleness evaluation, security scan, review-meta documents, and usage ledger. Agent Studio sees typed outcomes and references, not the internal review graph.
  • Coding Agent Chat remains a renderer and pure event-contract library. Hosts choose persistence and telemetry adapters. The shared library never imports an Agent Studio client.
  • Token Economy keeps pricing, routing, benchmark, quota, and estimator logic pure and dependency-free. Agent Studio owns operational evidence and decisions around those calculations.
  • Token Economy website remains static when deployed statically. Local telemetry is available only through an explicit localhost host or adapter; there is no hidden analytics script.
  • Voice Lint keeps lint rules, domain result semantics, and any audio or transcript handling. Only redacted operational and aggregate usage signals may cross into the collector.
  • Agent Studio does not become the database for another product, copy raw product state into tasks, or require itself to be running for another app to work.

Positioning statement

Agent Studio is the local portfolio operations and orchestration layer. It connects product telemetry, delivery evidence, CI/CD state, alarms, and bounded remediation into one reviewable Activity and decision surface. It manages across products without absorbing their domain cores.

§7Pilot and rollout plan

Why Quality Studio before Coding Agent Chat

Quality Studio has a server process, stable structured lifecycle events, explicit error events, run IDs, review evidence, and a durable per-repository usage ledger. The pilot can add a file sink and collector adapter at existing seams without changing review semantics. Coding Agent Chat is deliberately host-agnostic and browser-capable; making it the pilot would test host integration and browser buffering before the central case loop is proven. That is valuable later, not first.

Pilot rule, fully specified

  1. Input: event=quality.review.failed, sourceApp.id=quality-studio, level Error or Fatal, a non-empty run ID, and redaction version org-local-v1.
  2. Fingerprint: rule version, event, error code or type, review kind, and repository-relative component group. Error message and file path are not keys.
  3. Window: three events in 24 hours from at least two distinct run IDs. Fatal bypasses the count but not redaction or dedupe.
  4. Case: one Watcher Problem with count, first seen, last seen, affected Quality Studio repository registration, and runtime-event references.
  5. Action: Task API creates one Backlog card in Quality Studio, tagged telemetry-candidate and healing. The card requests reproduction, regression coverage, fix, and the original event measurement.
  6. Resolution: card completion alone is insufficient. The case resolves after a successful comparable review and a seven-day window with no matching failure, or after an attributable operator dismissal.

Rollout order

Quality Studio error pilot → Agent Studio internal normalization → Coding Agent Chat host adapter → Token Economy local website host → Voice Lint after inventory → all newly registered apps through the conformance gate. The order front-loads durable server-side signals, then proves browser and static-host constraints, and leaves the unverified repository until its boundary can be inspected.

§8Operator decisions

Decision request

  1. Approve Option C, hybrid local bus, with app-local Product Runtime Events as raw truth, Agent Message Bus as management projection, and local HTTP or SignalR as acceleration only.
  2. Approve Quality Studio quality.review.failed as the pilot, using the specified three-in-24-hours rule and a backlog-only healing card.
  3. Approve Agent Studio as the local portfolio operations hub, with explicit product-domain boundaries and no cloud telemetry dependency.
  4. Approve observe-only as the default for every new rule. Card creation requires a reviewed deterministic policy; automatic execution requires a separate existing Watcher recipe and authority decision.
