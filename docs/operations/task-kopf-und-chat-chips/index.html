Drei visuelle Defekte aus dem Operator-Review vom 08.08., kartiert mit file:line-Belegen. Vorgabe des Operators für die Tab-Leiste: bei Platzmangel nie überlappen — entweder nur Icons zeigen oder überzählige Tabs in ein Drei-Punkte-Menü.

Datum 2026-08-08 Status decision-pending Umsetzung Karte liegt im Backlog, Start nach GO

01Defekt: Tabs überlappen bei Platzmangel

Die Tab-Leiste ist die geteilte PaneTabsComponent, zweimal nebeneinander (Prompt-Pane: Overview/Timeline/Evidence/Code Review/Docs; Protocol-Pane: Task/Activity/Result). Der Host ist shrinkbar (min-width: 0), aber .pane-tab__label hat kein text-overflow: ellipsis — anders als der Pane-Header-Titel. Kein Responsive-Breakpoint berührt die Tab-Leiste; die Quetschung entsteht über den nutzergezogenen Pane-Splitter. Ergebnis: Labels laufen übereinander („Evider…", „Code Re", abgeschnittenes „Ta").

Beleg: pane-tabs.component.scss (kein Ellipsis am Label), task-detail.scss Breakpoints 1200px/720px (Tab-Leiste unberührt), task-detail.html ~105–195 (Panes-Reihe).

Variante A — Icon-only-Modus

Variante B — Overflow-Menü (Empfehlung)

Empfehlung

Basis-Fix in jedem Fall: text-overflow: ellipsis + Mindestbreite je Tab, damit Überlappung strukturell unmöglich wird. Darauf Variante B als Responsive-Verhalten (Container-Query auf die Leistenbreite, kein globaler Breakpoint — die Enge entsteht durch den Splitter). Variante A nur, falls B in der Praxis zu viel springt; die Messlogik (ResizeObserver je Leiste) ist für beide identisch, ein späterer Wechsel ist billig.

02Defekt: Branch-Chips „main — / main —"

Das Escalation-Banner rendert zwei Merge-Segmente als {label} {merged ? ✓ : —}. Die Labels kommen aus integrationBranch/releaseBranch der Karte. Bei Projekten, deren Integrationsbranch der Release-Branch ist (AOW, QS: Integration direkt auf main), sind beide Segmente identisch — es erscheint „main — main —". Der nackte Gedankenstrich als „nicht gemergt"-Zustand ist zusätzlich unlesbar.

Beleg: escalation-summary.component.html ~29–42, task-card-view-model.ts buildMergeSignal ~857–935 (Label-Fallback-Kette).

Vorschlag

  • Wenn integrationBranch == releaseBranch: nur EIN Segment zeigen.
  • Zustand statt Interpunktion: main ✓ gemergt bzw. main · ausstehend (Text statt nacktem „—"); Tooltip mit SHA.

03Defekt: Chat-Header-Chip überlappt

Der Ausführungs-Chip im Orchestrator-Side-Sheet (.sheet__execution-context) steht in einer Kette aus drei min-width: 0 ohne Mindestbreite. Zeile 1 (Host-Label) und der Repo-Teil haben Ellipsis — die Revisions-Zeile „main@sha" (.sheet__execution-revision) hat weder overflow: hidden noch Shrink-Fähigkeit. Wird der Sheet schmal (Resize-Clamp bis 360px), ist sie das einzige unkomprimierbare Element und kollidiert mit dem Label darüber.

Beleg: orchestrator-side-sheet.component.scss 48–108 (Asymmetrie 79–84 vs. 105–108), sidesheet.component.scss 45–53 (Header-Row ohne wrap).

Vorschlag

  • Ellipsis + min-width: 0-Floor auch für die Revisions-Zeile; SHA auf 7 Zeichen kürzen, voller Wert im Tooltip.
  • Chip erhält eine Mindestbreite; darunter klappt er auf Icon+Punkt-Status (Details im Popover) statt zu kollidieren.

04Entscheidung

  • Tab-Leiste: Variante B (Empfehlung), Variante A, oder Hybrid?
  • Branch-Chips: Ein-Segment-Kollaps + Textzustand — GO?
  • Chat-Chip: Ellipsis-Symmetrie + Mindestbreite + Kompakt-Zustand — GO?
