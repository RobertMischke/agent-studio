02Ownership

The system remains in the product repository. The seed, isolated stack, capture specs, and runbook live in agent-taskboard. Website, marketing, and presentation consumers use generated PNGs through their sync pipeline or the committed assets.

Operator decision recorded on 09.08.

The existing-data-only rule is retired. Documentation and marketing captures use the sanitized, deterministic snapshot and the --pinned source class. Task evidence continues to use --real, --mocked, or --composite because those labels describe run evidence, not documentation capture data.

03AGT-2530 delivery

  • Expanded shot list: a populated board hero and a large task-detail decision view, each in light and dark themes.
  • Pinned decision task: DEMO-9 includes evidence files, a review verdict, a diff, screenshot attachments, and a recorded Needs decision state.
  • Rendered annotations: at most three labels per landing-page shot, inserted into the browser DOM by the capture spec and controlled by PW_PRESENTATION_ANNOTATIONS.
  • Explicit snapshot refresh: a real board and task can be exported through a deterministic sanitization step. Normal capture never reads the source workspace.

04Decisions

  • --pinned is the source class for documentation and marketing captures.
  • The Visual Documentation Library no longer has an existing-data-only rule. Its images come from the committed deterministic snapshot.
  • Task evidence retains the existing --real, --mocked, and --composite classes because they describe run evidence.
  • Deriving a new seed from real data is an explicit, reviewed update act, never a live capture dependency.

05Delivery split

  • AGT-2530: extend the ADR-0056 pipeline, seed the decision task, render annotations, add --pinned end to end, and update the runbook and storyboard.
  • WEB-17, depends on AGT-2530: update the website manifest path, accept pinned assets in sync, and replace the landing-page screenshots.
