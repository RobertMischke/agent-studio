Decision brief

Recommended: retain application ownership of status.md, restore V1 finalization parity, and make Result finalization an awaited post-core gate. A missing generated Result must retry the summary step, not the completed core agent run. After a bounded retry budget, the card should expose a typed degraded Result state and remain reviewable without presenting the scaffold as normal success.

Root cause: the fresh-run prompt says not to rely on a hand-written status.md. The legacy artifact endpoint honors FinalizeResult=true; the V1 client branch uploads artifacts individually and drops that intent. The V1 Task Server persists artifacts and completion but has no summary-generation action.

Adjacent defect: MKT-21 proves a separate terminal-signal false negative. A post-run [worker-head-advanced] line invalidated an already logged [[TASK_DONE]], causing a needless core reissue.

MKT-21 terminal sequence

Run 1 logged [[TASK_DONE]] and a clean exit. The next durable line was [orchestrator] [worker-head-advanced]. The parser treats every orchestrator, supervisor, or user line after a sentinel as resolution, except one narrow technical marker. It therefore hid the valid Done signal. Fifteen minutes later the orchestrator reissued the card to obtain a clean terminal closure.

Run 2 also logged Done and exited cleanly, but another reissue followed. The durable log establishes a second false negative; it does not preserve enough concurrent ordering to assign that second miss to one exact race. Run 3 was accepted, then summary generation ran for 14.5 seconds.

7Decision options

A. Application-owned finalization gate

Recommended

Restore V1 parity and define a post-core Result-finalization step that is awaited before clean review closure. Retry only summary generation. Preserve the scaffold as an explicit degraded fallback after bounded exhaustion.

Effort: Medium. Runner client, V1 coordination boundary, lifecycle policy, and local/remote matrix tests.

Risk: Low to medium. The main risk is added review latency and backward compatibility during protocol rollout.

B. Agent-authored status duty

Alternative

Require Concept and Planning agents to write status.md alongside the dossier or report. Define precedence between agent text and generated text and remove the conflicting fresh-run instruction.

Effort: Small to medium. Prompt, validation, and ownership migration.

Risk: High. Prompt compliance is probabilistic, two writers can overwrite each other, and Coding versus Concept semantics diverge.

C. Scaffold as the normal concept Result

Alternative

Declare the dossier the sole narrative result and make the system scaffold the expected card summary. AGT-2552 would present its origin compactly and the dossier link would carry the decision content.

Effort: Small. Contract documentation and presentation.

Risk: Medium to high. Summary outages become normal, Result quality differs by mode, and operational regressions lose a useful signal.

D. Strict missing-file completion failure

Rejected shape

Reject clean completion whenever status.md is absent, without separating core completion from summary finalization.

Effort: Medium.

Risk: High. It converts a summary-side failure into expensive agent reissues and repeats the MKT-21 failure pattern.

8Recommendation

Application ownership with an explicit degraded state

  • Keep the dossier or report as the primary domain deliverable and status.md as the application-generated card summary.
  • Carry Result-finalization intent through V1, or move summary generation into a server-side post-step with equivalent durable evidence.
  • Await that step before a clean Result is claimed. A failed summary retries independently and never reopens the completed core run.
  • After bounded exhaustion, retain the honesty scaffold but label the Result as degraded. AGT-2552 presentation remains valuable for that fallback.
  • For AGT-2548, require the agent to publish the dossier and write its path to results/deliverables.md. The application finalizer should extract or receive that path and place it in generated status.md. Do not make a hand-written status file the canonical dossier contract.
  • Replace raw-log sentinel invalidation with latest-run typed terminal evidence. At minimum, technical post-run events such as worker-head-advanced must not resolve [[TASK_DONE]].

Decision requested: approve Option A, keep Option C only as the degraded fallback presentation, and reject agent-authored status.md as the primary repair.

9Implementation slices

This dossier proposes work only; it does not create or implement these slices.

  1. V1 Result-finalization parity: preserve the finalization request across negotiated transports and prove a real generated Result for a remote Planning or Concept run.
  2. Result-finalization lifecycle: model summary generation as an awaited post-core step with bounded retry and a typed degraded terminal state, without rerunning core work.
  3. Terminal-evidence parsing: make typed latest-run completion authoritative and add the MKT-21 worker-head-advanced sequence as a regression case.
  4. Dossier linkage and fallback presentation: align AGT-2548 link publication with generated Result ownership and AGT-2552 scaffold presentation.

Evidence boundaries

The inventory proves the current marker stock and the V1 contract gap. It does not prove a statistically reliable Concept-versus-Coding prevalence difference because only one card is stored as Concept and semantic concept cards such as AGT-2355 are classified as Coding. The exact ordering behind MKT-21's second false negative is also unresolved; only the first false negative has a deterministic parser explanation.
