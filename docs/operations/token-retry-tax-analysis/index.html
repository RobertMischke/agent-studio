05Session continuation and route choice

The host runs codex-cli 0.144.1. It supports codex exec resume [SESSION_ID] [PROMPT], explicit session UUIDs, --last, stdin prompts and model overrides. The CAR request already carries a nullable ResumeSessionId. The runner uses it for one bounded recovery after a run exits without the required terminal sentinel. It does not carry the session into a later conflict/requeue generation. Nightly runner specs therefore had resumeSessionId: null, and every re-round opened a new rollout id.

Required CAR and task-state changes

  1. Persist the captured Codex session UUID on the fenced run attempt and expose it to the next attempt-chain generation.
  2. Resume only when task key, provider, clean-context identity, repository, worktree path and branch lineage still match. A mismatch is a typed fresh-run decision.
  3. Pass a compact requeue delta: current base SHA, conflict paths, new steer and verification plan. Do not resend the original full prompt as a new task.
  4. Record inputSessionId, capturedSessionId, resume decision, rejection reason and per-generation token usage in the durable ledger.
  5. Permit one resumed mechanical continuation. A semantic conflict, stale or missing session, provider change, or failed deterministic gate falls back to a policy-qualified fresh attempt.

Nightly counterfactual

Conflict rounds reported 22 quota crossings. A resumed-round SLO of 10% of the cold token envelope implies 2.2 points consumed and 19.8 points saved. An 80% saving floor still saves 17.6 points. This range is the estimate to validate in a pilot, not a guaranteed property of the CLI.

Model and thinking level

TE-22's delegation-economy rule supports bounded cheap execution, but the canonical model-routing policy controls the floor. A clean, mechanically provable rebase should be performed by the platform with no model. If an agent is needed and the diff remains trivial with deterministic verification, Luna/medium is the policy route, although its quality evidence is explicitly provisional. A standard reversible one-subsystem adjustment may use Terra/medium. Semantic conflicts must be re-scored: unclear bugs require at least Terra/medium, public or three-subsystem contracts require Sol/medium, and leases, fencing, distributed authority or credible data loss remain Sol/xhigh.

At unchanged token volume, TokenEconomy prices Terra at 40% of Sol and Luna at 4% of Sol. Applying those price ratios only as a quota sensitivity gives 13.2 or 21.12 points saved from the 22 conflict points. Subscription quota buckets are not API dollars, so these are scenario bounds, not forecasts. Session continuation and model substitution overlap and must not be added.

08Method, provenance and limits

  • Token source: all rollout JSONL under /home/agent/.local/state/agent-studio/clean-context/codex/*/sessions/. Incremental last_token_usage values were summed only after the 68% anchor and through the event first reporting 95%. The complete bounded coding ledger is coding-session-ledger.csv.
  • Card source: current task records and prompts were read through the Task API for AGT, QS and TE cards. Prompt steer sections identify the conflict/rebase rounds. Nightly card tokenSummary fields were null, so rollout reconstruction is explicit.
  • Point attribution: whole points follow the session first reporting each increase. Integer rate-limit telemetry cannot reveal fractional concurrent attribution.
  • Review source: agent-runner-review.service journal lines and durable review specs/results. Reviews execute deterministic commands and produced no Codex session under review-work. The 58 completed claim-to-terminal segments are listed individually in review-attempt-durations.csv; the other 37 claims are explicitly censored at 10:00 CEST.
  • Cost source: TokenEconomy NuGet 0.3.2, resolved on the host. Cached input is separated from uncached input before applying the historical price.
  • Reproducible snapshot: exact totals, point reporters, unit medians and incident counts are retained in docs/operations/token-retry-tax-analysis/evidence.json.
