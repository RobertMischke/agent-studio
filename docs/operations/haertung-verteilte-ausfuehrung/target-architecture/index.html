Concept in six sentences

  1. The Task Server is the single truth — store, API, leases, provenance, management/recovery API. It never executes work and never calls an LLM.
  2. The Orchestrator Engine is its own process next to the Task Server, talking only through the public API. Runs are server state, not process children — an Engine restart orphans nothing (the one-process past did, empirically, on 23–24 Jul).
  3. The Runner is one daemon per host: claim → worktree → CLI slot → deliver via result-SHA handoff. It keeps itself alive (systemd) and reconnects with backoff.
  4. Agent Studio is a pure client with its own release cycle; it needs an offline indicator, nothing more.
  5. Quality is a contract, not an actor: the Engine executes gates/aspects/council; the Task Server keeps the evidence. This single sentence is where Architecture and Quality Layer meet.
  6. Nobody supervises anybody. Every actor keeps itself stable; the Task Server passively records last-seen per actor and the Deck makes it visible. No active pinging, no supervision hierarchy, no split-brain questions.
