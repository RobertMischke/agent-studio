Ein Vorfall ohne Eintrag hier gilt als nicht aufgearbeitet.

Die Phantom-Welle

11.07.2026, abends
Problem
~29 Karten der Abendwelle als „done“ gemeldet, aber auf origin kam kein einziger Commit an. xhigh-Compute-Arbeit unwiederbringlich zerstört (kein dangling commit auffindbar).
Root Cause
Drei gleichzeitige Defekte („die drei Löcher“):
  • AGT-2149: Host ohne Git-Push-Credentials (Deploy-Keys per Org-Policy deaktiviert) — jeder Push scheiterte.
  • AGT-2148: Daemon-Prompt ohne Completion-Protocol → nie ein Terminal-Sentinel → outcome Unknown → serverseitig als „Completed out-of-band“ verbucht (Erfolgs-Default für ein unbekanntes Ergebnis).
  • AGT-2147: Teardown machte worktree remove --force ohne Commit/Push — und lief nach der bereits gemeldeten Completion, Fehler verschluckt.
Tiefenstruktur: Completion war zeitlich vor und logisch unabhängig von jedem Push.
Maßnahme
Reihenfolge invertiert und gegated: Teardown committet, pusht, verifiziert (ls-remote-Gegenprobe) — erst dann Complete mit SHA. Push-Fehler ⇒ WorktreeSalvageException, Worktree bleibt, Karte eskaliert statt „done“. Startup-Push-Probe; schreibunfähige Runner melden sich read-only, Claims werden verweigert. Deploy-Key-Policy geflippt, Key am Repo.
Status
deployed 12.07. — Heilungsbeweis: AGT-2123 lief danach komplett durch (outcome Done, salvage-push secured=True).
Referenzen
AGT-2147/2148/2149 · runner/GitWorkspace.cs, runner/RemoteTaskRunner.cs, runner/GitPushProbe.cs, runner/SentinelScanner.cs · Handoff lage-kontext-handoff-2026-07-12.md

Gate-Test-Stufe wird Falsch-Eskalations-Fabrik

12.07.2026
Problem
Mit dem Nacht-Deploy bekamen Karten-Gates eine Test-Stufe — und vier latente Rot-Quellen (Namespace-Guard, monatslatente Fixture, Label-Drift, Live-Checkout-/Perf-Polizei) ließen gesunde Karten reihenweise durchfallen. Zusätzlich: Gate-Timeout 300 s bei ~8 min Suite („exit n/a“ = Timeout, kein roter Test), BuildProfile-Validierung läuft im leeren Worktree-Kontext (MSB1009) und blockiert Auto-Pickup.
Root Cause
Maschinen-/lastabhängige Tests in parallelen Karten-Gates; Timeout-Default nicht an Suite-Dauer angepasst; Validierung gegen falschen Kontext.
Maßnahme
MachineBound-Konvention ([Trait("Category","MachineBound")]) + Gate-Filter Category!=MachineBound; Timeout auf 900 s; Workaround: Status direkt in project-settings.json auf pipeline-ready.
Status
Workarounds aktiv Validierungsbug offen — strukturelle Antwort ist die Hermetik (Hauptseite §5).
