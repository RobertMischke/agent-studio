Zielbild in Kürze

Agent Studio orchestriert Coding-Agenten: Karten laufen durch code → Auto-Review → Integration. Das Ziel ist ein verteiltes, container-isoliertes System, in dem Runner und Backend über ein sauberes v1-Protokoll (nie driftend) sprechen, jede Ausführung im Container-Default läuft, Agenten autonom selbst pushen, und die Verifikation hermetisch im selben Container stattfindet.

Die Schritte (vier Phasen)

0
Pipeline heilen — Runner aufs v1-Protokoll (behebt Auto-Review), Build-Gate scharf, Reste-Batch (2302 + 2375 + Modell-Routing-Backend).
1
Container-Default — Basis-Images pro Komponente, docker-compose up, Installer wählt Container vor, Self-Push mit Git-+CLI-Tokens, Isolation via Container.
2
Verteilte Plattform — Control-Plane (2129/2230/2277), CAR-Migration (2370–2373), gepaarte Releases (2132), Qualitäts-Ebene (2130).
3
SSH-Tunnel ablösen — Steuerung nur noch per API (2262); Token-Refresh-Konzept ohne Tunnel.

Feature- und Kleinkram-Karten fließen ab Phase 0 einfach durch die geheilte Pipeline. Details + Kartenzuordnung: siehe „Umsetzungsplan" unten.

Leitplanken (entschieden)

  • Container-Default, bei Neuinstallation sofort ab Installer vorausgewählt.
  • Isolation gilt dem Agent, nicht den Sourcen — alle Projekt-Sourcen + Nachbarrepos dürfen gesehen werden (bewusst). Worktree-Modell bleibt; ein Git-Checkout je Projekt.
  • Agenten pushen selbst (Git-+CLI-Tokens); CLI-Token-Refresh über die lokale Umgebung; perspektivisch kein SSH-Tunnel — alles per API.
  • Gepflegte Basis-Images pro Komponente; die Container-Def wird ein agent-gepflegtes Repo-Artefakt, das Image ein Sidecar; Verifikation läuft hermetisch im selben Container.
  • Spawn-Pfade konvergieren auf CAR — ein Ausführungspfad, damit Container/Mount/Token/Image nur einmal existieren (kein Drift).
