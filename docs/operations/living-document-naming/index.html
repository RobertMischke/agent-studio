01The name has to cover the whole lifecycle

The earlier “Workbench” label described a place where analysis happened. The product has moved past that model. The artifact is now a durable subject record with an active middle: it frames a question, holds decisions, relates implementation cards, receives delivery updates, and ends as documentation.

01 · EXPLORE

Evidence, alternatives, unknowns, and operator questions are assembled.

02 · DECIDE

Decisions are recorded in the same public, versioned artifact.

03 · IMPLEMENT

Related cards, lane dots, refresh cards, and pipeline updates keep the record current.

04 · DOCUMENT

The accepted outcome and its rationale remain as permanent documentation.

This makes the artifact broader than a requirements document and narrower than the whole project wiki. It is about one coherent case or initiative-sized subject. The product behavior, not an adjective, makes it living: card references expose current state, AGT-2580 writes delivery updates, and the documented lifecycle from AGT-2537 gives the record a quiet terminal state.

Current naming boundary

The operator confirmed “Dossier” on 11 August. AGT-2539 completed the one UI and documentation rename and is archived. Code identifiers, workbench.json, API routes, and the AGT-W* key family remain workbench* by prior decision. No second rename card or code migration is required.

02Weighted evaluation criteria

The weights deliberately favor meaning across time. A concise label that becomes false after the decision phase is worse than a slightly formal noun that remains accurate. Scores use a 1 to 5 comparative scale, where 5 is the best fit. Weighted totals are out of 100.

25%

Lifecycle fit. Covers exploration, decision, implementation, and permanent documentation. This is the highest weight because no stage is optional.

20%

Truth-of-behavior fit. Does not hide that related tasks update the artifact. It should still make sense once updates stop because the outcome is documented.

15%

Public open-source register. Understandable English for contributors outside one company, without implying a private corporate ceremony or a standard the project does not implement.

15%

Collision resistance. Avoids confusion with *.spec.ts tests, the docs/ wiki, Epics, runtime logs, the ADR archive, and established external processes.

10%

UI brevity. Works in a navigation noun, a compact header, a copyable key row such as AGT-W4, empty states, and spoken references without abbreviation.

8%

German operator ergonomics. Easy to say daily in a German-speaking operating context while the public product language remains English.

7%

Rename attention cost. AGT-2539 makes the mechanical sweep relatively cheap. The score instead captures vocabulary churn, review attention, public copy changes, and muscle memory.

Weight order in the matrix: LF lifecycle fit, TB truth of behavior, UI brevity, OS open-source register, CL collision resistance, DE German ergonomics, RC rename attention cost.

04What adjacent document cultures actually imply

Borrowing a familiar label also imports its process. Those imports are useful evidence, but none covers the complete Agent Studio lifecycle.

Shape Up pitch

Basecamp defines a pitch as the formal write-up of shaped work for a potential bet and reuses it at kickoff. The team then discovers and tracks tasks while building. This validates the shaping and handoff part of the dossier, but “Pitch” stops naming the artifact once delivery updates and permanent documentation become first-class. Principles of Shaping; Hand Over Responsibility.

Amazon PR/FAQ

Amazon describes PR/FAQ as the central Working Backwards narrative for defining the customer experience, vetting an idea, and reaching clarity before build approval. It is a strong decision instrument, but its launch narrative and company-specific ceremony would misname general technical, operational, and architectural dossiers. Amazon’s account of Working Backwards.

RFC processes

The RFC series spans standards, methods, research, and information, but an RFC becomes an immutable publication. Updates and obsoletions are metadata or later RFCs. That is valuable archival discipline and the opposite of in-place task-driven maintenance. RFC Editor: What Is an RFC?

ADR practice

An ADR captures one significant decision and its rationale; a collection forms a decision log. A dossier can contain multiple decision points plus exploration and implementation evidence, so “ADR extension” would damage an already precise public term. Architectural Decision Records.

Living Documentation literature

Cyrille Martraire’s work presents living documentation as knowledge that evolves across the development lifecycle and stays current through well-crafted artifacts and automation. The relevant lesson is operational: liveness must be maintained, not merely announced in a title. AGT-2580 is therefore stronger evidence than the adjective “Living.” Living Documentation by design.

Executable specifications

Cucumber uses “specification” for plain-text scenarios that can be executed to check whether system behavior conforms. Agent Studio dossiers may include behavior, but also policy choices, visual options, incidents, delivery state, and documentary outcomes. “Living Spec” would imply executable coverage that the artifact does not guarantee. Cucumber introduction.

05Decision rationale and runner-up

01 · RECOMMENDED

Dossier

Short, durable, collision-resistant, and equally usable in English and German. It names the subject record rather than one phase or one update mechanism.

02 · RUNNER-UP

Living Dossier

The documented second choice preserves the right noun, but adds length and an awkward permanent-state claim.

COPY RULE

A living dossier

Best explanatory phrase, lower-case when descriptive: “A dossier is a living record from exploration through documented outcome.” The UI noun remains Dossier.

Why the accepted decision avoids a second rename

No. There is no material semantic defect in “Dossier” to justify reopening the product noun. A dossier is a collected record about one subject; adding evidence, decisions, task state, and delivery notes is normal growth, not a category error. The documented end state also matters: a completed dossier remains accurate when it is stable and no longer “living” in the active sense.

The confirmed decision avoided a second naming reversal while AGT-2539 completed the existing rename. Choosing a new label would have invalidated newly written public copy, reopened operator vocabulary, and made the delivery sweep more complex. That cost was modest but real, and “Living Dossier” added explicitness without enough new meaning to pay for it.

Why “Living Spec” is not the runner-up

It wins only on the active-update signal. It loses on scope and collision: many dossiers are not normative behavior specifications, and this codebase already uses “spec” for tests. The name would tell contributors to expect executable truth that the product does not provide.
