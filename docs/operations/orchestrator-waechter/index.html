Global Orchestrator Watcher

An intelligent layer above hard delivery invariants: it detects troubled cards across projects, assembles evidence, applies only proven recovery recipes, asks a strong model for bounded analysis when uncertainty remains, and publishes every problem, decision, action, and resolution in Activity across projects.

Recommendation

Approve an observe-first global Watcher, then add a narrow autonomous allowlist. Slices 1 and 2 should make incidents durable, visible, and strongly analyzed without mutating task or Git state. Slice 3 may autonomously re-register an unchanged runner and issue a bounded rebase-steer or existing-policy requeue through the application API. Fence transplantation stays approval-gated until a shadow cohort proves its scope checks and gates. Conflicts, scope changes, invariant waivers, and protected-branch writes always stay human-owned.

§1Mandate

Decision: approval is requested for the architecture, action allowlist, pilot gates, and operating placement. No runtime behavior changes in this dossier.

The Watcher is one global lifecycle coordinator for exception handling. It does not replace the project orchestrators, the runner, the pipeline, or the state machine. It consumes their typed facts and closes the gap between a visible fault and an evidence-backed recovery or decision.

Outcome

Every accepted trigger produces one correlated case that reaches resolved, decision-required, or an explicit bounded gave-up terminal.

Lifecycle authority

The Watcher owns case progression. Existing APIs, attempt fences, pipeline gates, merge queues, and reissue budgets remain the only mutation authorities.

Intelligence boundary

Models summarize and prepare decisions. Pure policy decides whether an action is allowed. A model response never writes task or Git state directly.

Operator promise

The cross-project feed separates an acute problem, a real human decision, work performed, and a finished finding. Raw model chatter is not the product surface.

Operational basis: the manual response recorded in Unverified Deliveries inspected salvage fences, performed card-scoped recovery, analyzed root cause, wrote a dossier, and requeued cards with steer notes. AGT-2543, AGT-2544, and AGT-2545 harden the substrate; this concept adds the reasoning layer above it.

This dossier treats AGT-2543 through AGT-2545 as required upstream contracts and does not assume that every contract is already deployed. Observe-only adapters may consume their final events once available or equivalent existing facts during the pilot.

Case contract

One WatcherCase is keyed by projectId + taskKey + attemptChainId + triggerClass + evidenceFingerprint. At-least-once inputs may reopen or append evidence, but they must not start duplicate model calls or repeat an action. The durable case stores its trigger, current phase, evidence references, action receipts, verification, model route, token use, operator epoch, and terminal reason.

Admission guards

  • Freshness: the task, attempt fence, operator epoch, and Git refs must still match when an action starts and when it commits.
  • Single ownership: one active case lease per task attempt. Project runners may continue normal work, but cannot run a competing recovery action for that attempt.
  • Noise control: retry events with the same evidence fingerprint append to the case. They do not create feed rows or model calls on every sweep.
  • Terminal discipline: an invariant-produced requeue or quarantine is not undone by the Watcher. The case reports it and can add context.

§3Capability ladder

The ladder is sequential and fail-closed. A later stage receives the receipts of every earlier stage. It may stop early when the problem is mechanically resolved.

Inspection package

The deterministic collector builds an immutable, size-bounded WatcherEvidencePack. It records absent evidence explicitly instead of substituting guesses:

  • task.json snapshot, lane, transition history, operator epoch, attempt-chain and current attempt identifiers;
  • typed run outcome, delivery envelope, integration status, grade and aspect findings, reissue and retry budgets;
  • bounded log windows around the trigger, plus full-log content hashes and paths for drill-down;
  • task, runner, fence, and integration refs; baseSha, resultSha, merge base, ancestry verdict, and remote presence;
  • card-scoped diff summary, changed-path inventory, result inventory, gate receipts, and baseline comparison;
  • related-case links and missing-artifact facts, including AGT-2555's generated status.md scaffold distinction.

Recovery recipes

RecipeRequired proofPilot authorityCompletion proof
Re-register The expected runner identity is unchanged, no competing live lease exists, credentials remain valid, and only an expired or absent registration blocks claims. Autonomous one bounded retry through the registration API. Capability heartbeat and claim eligibility become visible; otherwise escalate without repeated registration.
Rebase-steer No active CLI or merge action, a trusted task or fence ref exists, the base is stale, and the existing reissue budget permits one more attempt. Autonomous append a precise steer and request the existing requeue path. The pipeline, not the Watcher, performs Git work. The new attempt starts from current integration head and retains the prior evidence link.
Fence salvage Fence belongs to the exact task and attempt; ancestry is known; diff is card-scoped; no unexpected commits or paths exist; transplant is clean in a disposable worktree; required gates pass on the proposed subject SHA. A fence presence alone is never success.
Conflict packet Integration conflict or semantic overlap, with both sides and affected requirements identified. Human only no automated resolution. Operator chooses scope or resolution; a fresh normal pipeline attempt verifies it.
Loop break Repeated grade fingerprint or reissue without new evidence. Analysis only no additional blind reissue. Narrowed acceptance, new evidence, or an explicit human decision starts the next attempt.

Analysis receipt

The strong model receives only the evidence pack and a fixed response schema. Its receipt contains competing hypotheses, evidence for and against each, confidence, root cause, affected scope, a recommended recipe or decision, required approvals, verification, rollback, and unknowns. The pure action policy independently evaluates the receipt. Free-form prose cannot grant authority.

Card projection

The task shows one compact current Watcher panel, not a duplicate transcript: case id, status, last verified finding, current or proposed action, evidence links, and decision owner. Each Watcher transition also appends a structured timeline note through the application API. The panel deep-links to the case and the dossier or postmortem when one exists. Missing status.md remains a separate evidence fact owned by AGT-2555; the Watcher must not treat a generated scaffold as agent-authored proof.

Workspace aggregate

The global header shows open problems, decisions required, actions running, and rescues verified in 24 hours. Counts are sums of visible cases and respect project access. The normal feed retains its project and event filters. Strong-model tokens and historical cost state appear on the analysis row; unknown price is shown as unknown, never zero.

Live delivery

AGT-2535's proposed SignalR seam provides the pattern to reuse: persist first, publish a project-scoped event on the existing TaskHub, treat subscriber failure as best-effort, and refresh a complete snapshot after reconnect. The Watcher adds a stable watcherCaseUpdated envelope and an append-only feed projection. Authorized clients join project groups; the workspace feed merges only the groups they may read. A dropped socket cannot lose the incident because the snapshot endpoint rehydrates from the durable case store.

Noise rule

Every state-changing Watcher action is traceable, but identical checks are rollups, not feed rows. A periodic check that finds no new evidence updates counters on the case. It does not create an Observation every five minutes.

Spend controls

  • One strong call per evidence fingerprint. A second call requires materially new evidence or an operator-requested alternative.
  • Batch stale signals into a deterministic project rollup. Do not ask a model to rediscover the same substrate fault for ten cards.
  • Cap concurrent strong analysis globally and serialize it per project. Priority affects waiting time, never the correctness floor.
  • Record selected route, policy version, reason, tokens, quota bucket, price status, and case outcome. Calibrate the estimates after 30 resolved cases per trigger family where volume permits.
  • When the strong route is unavailable, P1/P2 cases wait visibly or ask for an override. They never silently downgrade. P0 cases surface an acute capacity problem.

§6Authority boundary

OwnerResponsibilitiesExplicit non-goals
Mechanical layer
AGT-2543 / 2544 / 2545		 Truthful completion and integration, envelope and fence guarantees, automatic policy requeue, distinct telemetry, stale detection and alarms. It does not infer root cause, compare competing recoveries, or write an operator dossier.
Watcher Correlated incident lifecycle, evidence packaging, exact recipe selection, allowlisted recovery requests, bounded analysis, decision preparation, card and feed reporting. It does not waive gates, mutate task storage directly, force-push, invent integration truth, or become a second scheduler or merge queue.
Human Scope changes, semantic conflict resolution, destructive or protected-branch operations, security and permission decisions, invariant exceptions, budget overrides, and promotion of new autonomous recipes. A human is not required to repeat mechanical evidence collection or approve a proven no-risk registration refresh.

Autonomy classes

  • A0, read-only: inspect, correlate, analyze, and report automatically.
  • A1, reversible and bounded: existing-identity re-registration, precise steer append, and policy-approved requeue through the API. Idempotent receipt and verification required.
  • A2, prepared: fence transplant candidate, clean rebase proposal, or non-trivial retry. The Watcher prepares commands, SHAs, gates, and rollback; a human confirms.
  • A3, human-only: force push, history rewrite, semantic conflict, cross-card scope, failed-gate waiver, permission elevation, protected branch override, or destructive cleanup.

Non-negotiable invariant

The Watcher works on invariant signals. It cannot suppress them, mark a card complete without their proof, or reinterpret missing evidence as success. If its own analysis disagrees with AGT-2543, AGT-2544, or AGT-2545, the result is a visible decision or defect report, not an override.

§7Operating model

Placement

The logical coordinator belongs beside the global Control Plane, not inside the local Studio UI and not inside one project runner. It needs workspace-wide task facts, a durable case store, global deduplication, and one lifecycle lease. Model and repository work is dispatched as bounded, attributable jobs to a runner with a watcher-analysis or read-only evidence capability. Existing pipeline services execute approved mutations.

ComponentPlacementReason
Watcher coordinatorSingleton hosted service in the Task Server or global orchestrator control process.Workspace truth, durable inbox/outbox, cross-project dedupe, no dependency on an open Studio client.
Evidence collectorRunner or host capability close to the repository and logs.Read refs and bounded artifacts without copying whole repositories into the Control Plane.
Strong analyzerDedicated analysis slot on an eligible runner.Uses live catalogue routing, records actual model and tokens, and cannot hold a coding or merge authority.
Action executorExisting task API, runner registration API, pipeline, merge queue, and transition services.Preserves fences, permissions, budgets, audit, and state-machine ownership.
ProjectionDurable case/read model plus TaskHub push.Card and Activity views converge after reconnect and remain access-scoped.

Cadence

  • Immediate: typed escalations, delivery failures, integration outcomes, and AGT-2545 alerts enter the durable inbox.
  • Five minutes: reconciliation joins task lane, attempt, Git integration, fence, runner registration, and open-case state to find silent anomalies.
  • Thirty minutes: AGT-2545 owns the accepted-without-integration threshold and repeated warning cadence. The Watcher consumes the emitted fact rather than starting a parallel timer.
  • Daily: a deterministic operating rollup reports trigger volume, resolution time, automatic actions, decisions, strong calls, tokens, and unknown-price rows. A model-authored news summary is optional and separately budgeted.

Self-monitoring

An independent health monitor, not the Watcher itself, evaluates a one-minute heartbeat and event watermark. Three missed heartbeats or a five-minute input lag produces a workspace Watcher unavailable Problem in Activity and system health. The coordinator reports queue depth, oldest unclaimed case, phase age, action retries, dedupe rate, recipe success, human reversals, strong-call latency, tokens, and spend status.

  • Restart replays the durable inbox and resumes cases by idempotency key.
  • An unavailable analyzer pauses only analysis-required cases. Mechanical invariants and normal pipeline recovery continue.
  • An action verification timeout fails closed, publishes the incomplete receipt, and blocks repetition until state is reconciled.
  • Global and per-project concurrency are bounded. There is no nested fan-out and no hidden subagent tree.

Pilot promotion

W1 and W2 may ship together in observe-only mode after AGT-2543 to AGT-2545 signals are integrated or adapted. W3 requires at least 30 shadow cases across its enabled trigger classes, zero proposed actions outside the allowlist, and no missed stale-evidence rejection. Fence integration must remain A2 until at least 30 operator-approved fence candidates have zero scope escapes, zero wrong-attempt attribution, deterministic gates on the exact subject SHA, and no human reversal. Promotion is per recipe, never a global autonomy switch.

Dependency reading

  • AGT-2543: authoritative acceptance and integration truth. The Watcher consumes its outcome and cannot weaken it.
  • AGT-2544: delivery envelope, salvage-fence reference, and regular recovery path. The Watcher handles exceptions after that policy has spoken.
  • AGT-2545: honest outcome counts and stale accepted-delivery signal. It is the Watcher's low-cost wake source.
  • AGT-2555: reliable status.md completion evidence and scaffold distinction. The Watcher reports missing proof without manufacturing it.
  • AGT-2535: durable-first, project-scoped SignalR projection and reconnect convergence pattern. It is an implementation seam, not a source task of this dossier.

§9Decision request

Requested operator decision

  1. Architecture: approve the global Control Plane coordinator with runner-hosted evidence and model jobs.
  2. First release: approve W0 to W2 as observe-only, with no task or Git mutations.
  3. Autonomy: approve A1 re-registration and rebase-steer or policy-requeue for W3, subject to the stated guards and kill switches.
  4. Fence policy: keep fence salvage A2 and approval-gated until recipe-specific promotion evidence exists.
  5. Model policy: approve Mini/high only for bounded compression, Sol/medium for ambiguous analysis, and Sol/xhigh for the existing hard-floor cases.

Recommended answer: approve all five items. This creates useful visibility and analysis before granting mutation authority, preserves the mechanical guarantees now being added, and turns today's manual rescue pattern into a measured, auditable progression rather than an all-at-once autonomous agent.
