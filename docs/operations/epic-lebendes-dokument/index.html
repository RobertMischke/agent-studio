Das Epic als lebendes Dokument

Ein Muster: Jedes Epic bekommt ein klares, sich selbst aktualisierendes Dokument als seine Sicht — zum Nachlesen in Ruhe. Der Betrieb (Tasks, Prompts, Status) sitzt daneben, nicht darin. Und wenn das Epic fertig ist, wandert das Dokument automatisch ins Archiv.

Typ Planung / Konzept Setzt auf Konzept-Pipeline · Epics · Wiki-Klassifikation · Live-Refresh (AGT-2367) Gate Sichtblick — Robert entscheidet

ADer Gedanke

Robert (26.07.): „Für mich ist der Prozess — klares schönes Dokument, was sich aktualisiert, ideal. Hier kann ich in Ruhe nachlesen." Genau das wird hier zum Muster erhoben. Ein Dokument wie das Remote-Gate-Doc ist kein Wegwerf-Text, sondern die ruhige, lesbare Sicht auf ein Vorhaben. Der laute, wechselnde Teil — welche Karte läuft, welcher Prompt, welcher Status — gehört sichtbar daneben, aber getrennt, damit die Sicht sauber bleibt.

BDer Flow: von der Idee bis zum Archiv

CMockup: eine Ansicht, ein Schalter

Roberts Nachtrag löst den Zielkonflikt: nicht zwei konkurrierende Layouts, sondern ein Schalter zwischen zwei Zuständen derselben Ansicht. Standard ist Ruhe — nur das Dokument, volle Breite, zum Nachlesen. Ein Klick expandiert den Betrieb in Panels/Reiter links und rechts. Der Wechsel Ruhe → Betrieb ist ein Toggle, kein Seitenwechsel.

Wie heißen die zwei Zustände?

Robert schlug CALM ⇄ COCKPIT vor und sucht einen besseren Begriff als „Cockpit". Kandidaten für den aktiven Zustand: CONTROL (CALM ⇄ CONTROL — sauber, beides „C", passt zum englischen Produkt), REGIE (Leitstand-Metapher), oder schlicht deutsch Lesen ⇄ Betrieb. Empfehlung: CALM ⇄ CONTROL als Produkt-Begriff, UI-Label deutsch „Ruhe / Betrieb". Entscheidung bei dir.

DLifecycle: das Epic steuert das Dokument

Der Clou, der Roberts Aufräum-Problem löst: Der Zustand des Epics treibt die Klassifikation des Dokuments. Kein manuelles „ist das noch aktuell?" mehr — das Dokument weiß, in welcher Phase es steht, weil das Epic es weiß.
