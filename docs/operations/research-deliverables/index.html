Operator convention

Research tasks deliver one primary HTML report

A research card is a report workflow, not a code workflow. Its one primary document is easy to find, supporting evidence stays navigable from that document, and the pipeline performs only the checks needed for a document handoff.

Effective 2026-07-28

Delivery contract

  1. Write exactly one primary document at results/report.html.
  2. Use the operations-document house style: self-contained HTML, inline CSS, light and dark themes, no external runtime dependency, and a problem/solution-first structure.
  3. Sources, raw data, and detailed analyses may be separate companion files. Link every companion from the primary report. Do not present loose siblings as the result.
  4. If the task also publishes to the Wiki, the Wiki HTML is the publication form of the same primary report. The managed delivery flow owns publication.
  5. The card Result tab presents report.html as the primary result in a sandboxed HTML viewer.

How research is recognized

SignalContract

Visible card cueThe Research mode pill on the card.
Prompt cueThe effective prompt contains a visible Research: heading and the delivery block below.
Settings dimensionPipelineTypes.Resolve(taskType, mode) maps Research to the AGT-2301 planning dimension, so coding-type overrides cannot leak into the report flow.
Pipelineread-only-task-pipeline, displayed as Lightweight report pipeline.

What runs

  • Loop guard
  • Model qualification
  • Optional preparation
  • Reissue open-items check
  • Research authoring
  • Primary-report validation
  • Human-review handoff

What does not run

Worktree, commit, merge, build, automated tests, Stylelint, code-review aspects, code-quality grade, regression radar, Wiki automation, and drift checks are excluded.

Copy-paste block for Research prompts

The runtime injects this block through the same mode-framing mechanism as the other context blocks. Prompt authors can also paste it into a card when the deliverable must be explicit before execution.

Research: This is a research run. Keep the task prompt and primary report visibly headed `Research:`.

Deliver exactly one primary document at `results/report.html`. Make it a self-contained HTML document in the operations-document house style, with inline CSS, light and dark themes, no external runtime dependencies, and a problem/solution-first structure. Supporting sources, raw data, and detailed analyses may be separate files under `results/`, but link every supporting document from the primary report. Do not leave an unstructured sibling list as the result. If the task names a Wiki destination, use the same HTML as the publication source; the managed delivery process owns publication. The card Result tab must present `report.html` as the primary result.

Card creation checklist

  • Select Research mode. Do not encode research only in taskType or free text.
  • Start the title or task prompt with Research:.
  • Name the Wiki destination when publication is required.
  • Name any expected companion data, but keep the main-report link list authoritative.
  • Accept only when the Result tab opens the primary HTML and the pipeline contains no code gates.
